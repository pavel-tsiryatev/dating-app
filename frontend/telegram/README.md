# CAMPUS · telegram

Telegram-клиент. **Пока не начат**: третий из трёх клиентов, которые мы пробуем
(сайт — [`../web`](../web), мобильное приложение — [`../mobile`](../mobile)).

Работает с тем же бэкендом [`../../backend`](../../backend) по контракту
[`backend/openapi.json`](../../backend/openapi.json). В схеме базы уже есть `users.telegram_id`.

## Предлагаемая схема

Бот + **Mini App**:

- **Mini App** — это сайт из [`../web`](../web), открытый внутри Telegram. Лента, анкета, чат и билеты не пишутся
  второй раз. Вход — по `initData`, который Telegram подписывает токеном бота; API проверяет подпись и выдаёт свой JWT.
- **Бот** (grammY или Telegraf на Node.js) — тонкий: кнопка «Открыть CAMPUS», уведомления о совпадениях,
  сообщениях и билетах, команды `/start`, `/help`, `/stop`.

Чистый бот без Mini App тоже возможен, но ленту с фото, загрузку фото и чат в нём придётся делать заново
на кнопках и диалогах.

## Что нужно от бэкенда

Подробности и приоритеты — в [`docs/AUDIT.md`](../../docs/AUDIT.md), раздел «Telegram».

1. `POST /auth/telegram`: проверка подписи `initData`, привязка `telegramId` к аккаунту после подтверждения
   почты вуза (студенческий статус по-прежнему подтверждается только почтой).
2. Канал уведомлений Telegram в `NotificationsService` (`sendMessage` по `telegramId`), отписка при блокировке бота.
3. Если бот сам ходит в API за пользователей — лимит запросов по пользователю, а не по IP: иначе все пользователи
   бота делят 120 запросов в минуту и 5 запросов кода.
4. Оплата: цифровые товары в Telegram (Premium) по правилам Telegram продаются за Telegram Stars;
   билеты на офлайн-события — через обычного провайдера. Решить до разработки оплаты.
